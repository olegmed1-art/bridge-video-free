# Архив рабочих версий 3.1 FREE

Правило проекта: перед изменениями, способными повлиять на распознавание, семантический QC, мастер-анализ или PDF, последняя подтверждённая рабочая ревизия сохраняется отдельно для быстрого отката.

Архив может храниться как защищённая архивная ветка Git с именем `archive/<revision>-<date>` и/или как снимок файлов. Основная пользовательская версия остаётся **3.1 FREE**; каждая техническая итерация получает новый `algorithmRevision`.

Первая зафиксированная стабильная точка:
- `3.1-free-master-analysis-r4`
- commit `2c7ba11f22f38a633c1123915bc6a7157f1e5bb7`
- архивная ветка `archive/3.1-free-r4-stable-2026-08-11`
- подтверждение: production run #7 завершён успешно.

Процедура изменения:
1. Проверить состояние текущей рабочей ревизии.
2. Если она подтверждена — сохранить архивную ветку/снимок.
3. Увеличить `algorithmRevision`.
4. Внести изменение без удаления исходных пользовательских файлов.
5. Прогнать локальные/структурные проверки и production validation на известной записи.
6. Сравнить качество с предыдущей стабильной ревизией, включая бриджевую терминологию и семантические ошибки.
7. Только после успешного сравнения считать новую ревизию стабильной.
8. При регрессии откатиться к последней стабильной архивной ветке и сохранить проблемную ревизию для разбора.
