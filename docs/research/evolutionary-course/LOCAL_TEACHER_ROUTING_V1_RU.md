# От ответа к следующему заданию — локальный адаптер преподавателя

2026-10-13 · ASSURED · кандидат; без production, PDF, сайта или записей mastery.

`evolutionary_course/teacher_routing.py::TeacherLesson` добавляет небольшой журнал сеанса и детерминированный выбор к существующему `teaching_step`. Задания выдаются через прежний `student_view()`, закрытый материал — через `exercise_version_fields()`. Граф берётся из `/candidate_dependencies/nodes` исходной спецификации; политика содержит только отображение полей ответа на узлы и приоритеты. Новый каталог и искусственные состояния профиля не создаются. Глобальный `adaptive_selector` сохраняет прежнюю роль выбора по подтверждённому профилю.

| Наблюдаемое локально | Следующее действие |
|---|---|
| Ответа ещё нет | Дождаться первого ответа |
| «Не знаю», неполный/неподдержанный ответ | Сохранить, ABSTAIN, запросить уточнение; подсказка доступна |
| Первый ответ совпал по полям | R1 как новый авторский перенос; объяснение остаётся для review |
| Ошибка исправлена до местной обратной связи | Отметить локальную самоправку, сохранить обе версии, перейти к R1; mastery не подтверждается |
| После подсказки ответ совпал | Отметить помощь; выбрать контрпример по фокусу подсказки |
| Ошибочные поля | Выбрать контрпример по приоритету существующего графа |
| Уже разобранный контекст повторяется | Явно пометить повтор/прежнюю помощь; не считать новой независимой попыткой |
| Две неуспешные выдачи одного контрпримера или набор исчерпан | Остановиться для преподавателя, без повышения уровня |

`PARTIAL` означает только проверку заданных структурированных полей. `ABSTAIN` означает отсутствие достаточного поддержанного ответа. В обоих случаях `learner_error=null`, mastery и criterion_met — null; ошибочное поле задаёт учебный фокус, а не диагноз. Свободное объяснение и все его версии сохраняются целиком. Несколько допустимых смыслов объяснения указаны в закрытых ключах; сравнения по точной фразе нет. Иной план розыгрыша не объявляется ошибкой из-за отсутствия в числовом ключе: его смысл требует review.

## Подключение экрана к преподавателю

```python
from evolutionary_course.teacher_routing import TeacherLesson

lesson = TeacherLesson("local-session-1")
view = lesson.current()  # prompt, issuance_id и границы локальной попытки

ack = lesson.record_response(
    command_id="answer-1", issuance_id=view["issuance_id"], response=response,
)
# ACK одинаково нейтрален для верного и ошибочного ответа: не содержит оценки.
# Ученик может прислать новую версию под новым command_id до обратной связи.
hint = lesson.request_hint(command_id="hint-1", issuance_id=view["issuance_id"])
decision = lesson.advance(command_id="feedback-1", issuance_id=view["issuance_id"])
next_view = decision["next_assignment"]
teacher_only = lesson.teacher_snapshot()  # не отправлять ученику
```

`response` сохраняет контракт `low-card-structured-response-v1`: schema, exercise_id, prompt_sha256, answers, explanation. Для честного «не знаю» можно сохранить строку; она останется UNASSESSED. `advance` — отдельное явное раскрытие feedback; не вызывать его автоматически перед возможностью самопроверки. Каждый новый ответ/подсказка/раскрытие имеет новый command_id. Повтор идентичной команды возвращает прежнюю квитанцию; конфликтный повтор, старый issuance или изменённый prompt отклоняется без записи. Hash связывает содержимое, но не удостоверяет личность.

Журнал хранится только в памяти объекта, сохраняет исходный ответ и монотонную историю помощи; перезапуск процесса теряет журнал. Новый пример после обратной связи несёт отметку прежней поддержки. Внешняя помощь и опыт неизвестны. Правильный текст по существу проверяет преподаватель; автоматический переход предварительный, а не признание понимания. Пределы: восемь ответов на выдачу, две выдачи одного задания, 128 команд. Подсказки, сброс новой выдачей и повтор команды не очищают поддержку.

## Два авторских контрпримера

- `counter.four-one`: ♣AKQ32 в руке, ♣765 на столе, известно 4–1. После данных A/K/Q и 5/6/7 у длинного защитника остаётся одна из J/10/9/8/4; любая старше 3 и 2. Сейчас готовых взяток на фоски **0**. Будущая выработка не оценивается.
- `counter.no-entry`: ♠A в руке, ♠5 и готовые ♣765 на столе; ход в руке, других собственных входов нет. Готовы **3** взятки, но A→5 оставляет ход в руке. Доступ не обеспечен. При отдельно данном ходе на столе эти три взятки можно получить сразу; абсолютная невозможность будущей помощи защитников не утверждается.

Оба шага расширяют тот же teacher interface; граф и предложение критерия освоения композиционно берутся из основной спецификации. Исходные E1/R1 и их ключи сохранены.

## Основание и явные пробелы

В `local_teacher_routing_policy_v1.json/pedagogical_basis` разделены авторские задания и существующее видеооснование. D2 interaction_f4442a16e69bedceb03f поддерживает объяснение 3–2 для пяти отсутствующих карт, а не самостоятельный счёт ученика. Методическая цель «вырабатывать взятки на фоски» — переданная поправка владельца; URL сохранён с пометкой, что беседа заново не читалась. Цельная цепочка в каталоге не зарегистрирована, автоматического соответствия исторических SKILL-* и candidate.skill.* нет. Для продольного пилота остаётся минимум два разных подтверждённых занятия с принятыми episodes. Этот запуск продольным пилотом не является. Старый EX-0002 не импортируется.

`ai_decision._search_choice`, EV, post-hoc DDS и `dds_training/v23_core.py` не используются и не меняются. Адаптер не ранжирует произвольные действия в бридже и не превращает одно действие в единственное правильное на основании внешнего solver. Он проверяет только явно поставленные поля авторской задачи; остальной смысл остаётся на review.
