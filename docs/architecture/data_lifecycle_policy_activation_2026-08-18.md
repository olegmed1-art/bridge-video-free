# Активация политики жизненного цикла данных — 2026-08-18

Каноническая политика: `docs/architecture/data_lifecycle_policy_v1_0.md`.

## Решение владельца

По прямой команде владельца проекта от 2026-08-18:

- внедрена классификация P0–P7;
- внедрён обязательный Deletion Gate;
- Google Drive назначен основным долговременным файловым хранилищем для крупных P0/P2/P3 объектов;
- Neon назначен system of record для identity/checksum/provenance/location/verification/audit metadata;
- GitHub Actions назначен временной рабочей средой, а не архивом;
- старое абсолютное правило «ничего не удалять без команды пользователя» отменено для технических, временных, дублирующих и безопасно offloaded объектов;
- абсолютная защита сохранена для P0 оригиналов/невосполнимых данных и для иных явно защищённых policy-классов;
- если безопасность удаления не доказана, удаление запрещено;
- automated cleanup обязан быть аудируемым.

## Precedence

При конфликте между прежней общей формулировкой хранения/удаления и `data_lifecycle_policy_v1_0.md` применяется новая политика.

Более строгие специализированные правила продолжают действовать, если они защищают:
- оригиналы/уникальные данные;
- teacher-authority и каноническую методику;
- production recovery/rollback;
- security/secrets;
- immutable migration history;
- evidence, необходимое для аудита и regression.

## Текущий технический предел

Активация policy не означает немедленное физическое удаление всех старых GitHub Actions artifacts. Очистка разрешена только через доступный delete mechanism и после прохождения Deletion Gate. Отсутствие delete-action не является основанием считать GitHub долгосрочным архивом: retention должен постепенно минимизироваться в workflow-конфигурации.
